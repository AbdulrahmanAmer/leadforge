# Send Outreach

Sending is a **bounded, audited extension** of a LeadForge lead sheet, not a separate product. It is dry-run
everywhere by default; nothing leaves the workspace without an armed config, a named human approver, and a content
hash matching what that human approved. Full protocol + guardrail detail: `references/outreach.md` (sending) and
`references/drafting.md` (writing the two model slots of a message). Never widen these guardrails to satisfy a
request. **You never run `--live` yourself** — the workspace owner arms it and names the approver.

This skill assumes a workspace already has a scored lead sheet from the `generate-leads` skill. Do not run
discovery/crawling here.

## Iron rules

1. Every `leadforge` / `leadforge outreach` command ends with one `LF_DIGEST {json}` line — that line is the result.
2. Never read raw files under `leadforge_data/` (unbounded) except the small NDJSON draft/packet batches this skill
   itself produces and reads.
3. Never paste message bodies, inbox replies, or bounce content back to the user — counts and classifications only
   (`references/outreach.md` "never paste message content").
4. `outreach.armed: true` is a config change only the workspace owner makes (`leadforge config set outreach.armed
   true`) — propose it, never set it yourself.

## Step 1 — Identity + mailbox (once per sender)

```bash
leadforge outreach identity add --label <identity-label> --from-email <you@sending-domain> --from-name "<Name>" \
    --postal-address "<postal address>" --privacy-url <https://...> --unsubscribe-mailto <stop@sending-domain> --json
leadforge outreach mailbox add --identity <identity-label> --address <you@sending-domain> --transport smtp \
    --config host_env=LF_SMTP_HOST --config port_env=LF_SMTP_PORT --config user_env=LF_SMTP_USER \
    --config password_env=LF_SMTP_PASS --json          # values are env var NAMES, never literal secrets
```

`<identity-label>` and `--owner-entity` (if the user's setup needs one) come from the user's own workspace — never
hardcode a label; ask what they want to call this sending identity.

## Step 2 — Doctor (sender health, before enrolling anyone)

```bash
leadforge outreach doctor --identity <identity-label> --json   # SPF / DKIM / DMARC / MX / warm-up — must be all ok
```

If any check fails, report it and stop; do not enrol or draft until DNS/mailbox health is fixed
(`references/troubleshooting.md` has the common DNS failure modes).

## Step 3 — Enrol + draft

```bash
leadforge outreach plan --campaign <campaign> --tier A,B --identity <identity-label> --json   # enrol eligible leads
leadforge draft export --campaign <campaign> --purpose client_campaign --max 40 --json
#   only for targets with no draft yet, or to redraft one: read the packet file; write drafts.ndjson:
#   {"target", "subject", "observation", "used_fact"} or {"target","abstain":true} — see references/drafting.md
leadforge draft apply --in drafts.ndjson --json          # mechanical no-fabrication gate; rejected drafts are counted
leadforge draft render --campaign <campaign> --out drafts/ --json   # files for the human to read
```

Never invent a fact in a draft — the gate rejects it, and the packet is the only source of truth. Abstain on
grade-C packets when the purpose needs personalisation.

## Step 4 — Human approval, then dry-run send

```bash
leadforge outreach approve --campaign <campaign> --all-drafted --approver "<human name>" --json
leadforge outreach send --campaign <campaign> --json     # DRY RUN (default): writes .eml files, sends nothing
```

Tell the user where the `.eml` files landed (the digest's `outbox_dir`/`artifacts`) and ask them to read a few before
anything is armed. Never edit a message after approval — it reverts to `drafted`.

## Step 5 — Live send (owner-gated; you do not do this alone)

Only after the workspace owner has set `outreach.armed: true` and named an approver:

```bash
leadforge outreach send --campaign <campaign> --live --i-am "<approver name>" --json
```

Report `sent` / `skipped_*` / `unknown` counts from the digest. A `paused` mailbox (bounce/complaint rate) means
STOP using it — do not route around the pause; tell the user.

## Step 6 — After sending

```bash
leadforge outreach sync --json           # ingest bounces/complaints/unsubscribes/replies — counts only
leadforge outreach status --json         # lifecycle + mailbox snapshot
leadforge outreach outcome add --business <id> --channel phone|email --result <...> --json  # feed scoring
```

To honor an opt-out immediately: `leadforge suppress add <email-or-domain>`.

## Doctor for this skill

`leadforge outreach doctor` is always the light, no-download check (SPF/DKIM/DMARC/MX/warm-up reads only) — there is
no heavy/`--full` mode here, unlike `leadforge doctor` in `generate-leads`.
