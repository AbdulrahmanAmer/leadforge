# v0.3 build plan — truth, coverage, outreach (decided 2026-09-02)

This is the binding worklist for the v0.3 release. It was decided by the owners on 2026-09-02 after a
measured assessment of the live UK auto-repair campaign (report: `.claude/POSITION.md` tail block).
Every unit below names its **owner** (one writer per file, always), the **files it may touch**, the
**interfaces it must honor**, and its **acceptance criteria**. A unit is done only when its acceptance
criteria pass in the full gate (`pytest -q && ruff check src tests`).

## Owner decisions (binding)

| # | Decision | Answer |
|---|---|---|
| 1 | Sending | **In scope with guardrails** (ADR-011). Dry-run default, approval bound to content, suppression at send time, caps + warm-up enforced. Still no SMTP probing, no dialer, no LinkedIn. |
| 2 | Channel | **Phone-first, email as second touch.** `Next Action` orders every row call-before-email. |
| 3 | Sender identity | **Hybrid per client.** Both models supported: client-owned domain (GainLev processes) and GainLev-owned domain. `client_id` on every identity, target, send and suppression row. |
| 4 | Paid dependencies | **None required.** Transport is pluggable (`file` dry-run, `smtp`+IMAP with any mailbox, adapters later); drafting is in-harness (agent writes drafts from CLI packets); domain resolution uses free methods only. ADR-012. |
| 5 | Freemail addresses | **Emailable after the plausibility check** (`validation.freemail_policy: linked`). Unlinked freemail is stored `risky`, never sendable. Entity type + lawful basis are still exported per row. |
| 6 | Director names | **Only when gated**: registry match passed the name-similarity gate, company is active, and a second source corroborates. Otherwise a company-level greeting. |
| 7 | Own-client ICP | Anyone who needs outreach **except other call centres** (SIC 82200 excluded by default in company mode). |
| 8 | Discovery rebuild | **Full 10-city tiled sweep** in the background after the code ships, plus the DVSA and Companies House registers merged by phone. |

## Measured facts that drive the design

- Live campaign: 12/30 queries ran (cap counted raw listings); 6 cities have 0 rows; 8/12 completed queries sit at Google's ~106 ceiling; 10 km grid tiles still saturated (110/100).
- DVSA active MOT stations (OGL CSV, quarterly, phone on 23,085/23,087): 1,045 in the 4 covered cities, 317 in our DB by phone. Companies House SIC 45200 active: 7,518 across the 10 cities vs 816 held.
- `grid.geocode` rejects "Manchester" in every spelling (same city returned twice; `_distinct_places` compares labels before coordinates) and resolves "City of Manchester" to a canal.
- gosom v1.17.4 is the latest release. Raw cache already carries `about` attributes, `order_online` links, owner review replies (358 places, 75 signed), `status` — all discarded today.
- Accuracy: 7 junk freemail rows tiered valid; freemail outranks `info@own-domain`; registry match has no name check (7–10% wrong company); dissolved companies unfiltered (26 DMs); `registry_profile` persisted only on the site-less path; 42% of heuristic people are review noise; `weak_social_presence` fires on 473/630 rows with zero evidence (115 "phantom" crawls stamped `crawled_at` with 0 pages); booking regex misses "Book a Service"; `industry_match` gives 0.1 to Google's own category strings (404 rows); size/geo/model factors constant; fit and contactability blended.
- Sendable funnel today: 816 → 194 email → 112 own-domain → 98 active Ltd + email → 45 A + DM + own-domain.

## Waves and ownership

Wave 0 is done by the orchestrator in the shared tree and committed before Wave 1 starts. Waves 1 and 2
run as parallel builders in **isolated worktrees**, each owning a disjoint file set, testing with
`PYTHONPATH=<worktree>/src python -m pytest tests/<own tests> -q`. The orchestrator merges, runs the
full gate, and runs a fresh-context reviewer on the critical units before accepting a wave.

### Wave 1 — data truth and coverage (parallel builders)

**A — Discovery coverage.** Owns `src/leadforge/grid.py`, `src/leadforge/pipeline.py`, `src/leadforge/providers/gosom.py`, `src/leadforge/normalize.py`, `tests/test_grid.py`, `tests/test_geo_guards.py`, `tests/test_discovery_coverage.py` (new), `tests/fixtures/gosom_sample.ndjson`.
- A1 Geocoder: compare coordinates first (two hits within 0.15° whose bboxes overlap are the same place); prefer `addresstype` in `city, town, borough, administrative, suburb, village, county` over amenities/waterways; honour `cfg.discovery.area_bbox[area]` as an explicit override that skips Nominatim; error messages name the fix. Acceptance: fixture Nominatim responses for "Manchester" (two rows, same city) resolve without error; "City of Manchester" fixture (canal first) picks the city row; an override bbox is used verbatim.
- A2 Saturation subdivision: in `run_discover`, when a tiled query returns `>= cfg.discovery.subdivide_at` listings, insert 4 child queries (same text, quadrant tiles, `tile_json.depth+1`) before marking the parent done; stop at `max_subdivisions`. Idempotent on resume (children persisted first). Acceptance: fake provider returning 100 listings produces 4 children at depth 1 and none at depth 3; a resumed run does not duplicate children.
- A3 Resume completes discovery: `run_pipeline(resume=True)` re-enters discovery whenever the latest run has `pending` or `degraded` queries, at any stage (the live run is `exported` with 18 pending). After discovery it proceeds through enrich → registry → score → export as normal. Acceptance: a run at stage `exported` with 2 pending queries re-runs exactly those 2 and ends `exported` again with the new businesses scored.
- A4 Honest estimates: `plan_counts` uses `cfg.discovery.est_min_per_query` (untiled) and `est_min_per_tiled_query` (tiled) and reports both counts. `plan` digest counts include `untiled_queries`, `tiled_queries`, `est_runtime_min`.
- A5 Keep GBP fields: `GOSOM_FIELD_MAP` gains `about, order_online, status, description, owner, reviews (user_reviews_extended|user_reviews)`; `normalize.to_business` writes `enrich["gbp"] = {"appointments": "recommended|required|none", "booking_links": [urls], "status": str, "owner_name": str, "reply_signatures": [first names from owner replies], "review_names": [first names credited in >=3 reviews], "reviews_captured": n, "description": str[:300]}`. Acceptance: fixture record with `order_online` and signed replies yields the expected dict; no field → empty defaults, never None.
- A6 Normalize dispatch: `to_business` uses `get_field_map(raw.provider)`; dedupe key for providers without `place_id` stays `na:` + name+street+city; a row with `phone` but no place_id also carries `phone_e164` so `db.upsert_business` can phone-merge.

**B — DVSA register provider.** Owns `src/leadforge/providers/dvsa.py` (new), `tests/test_providers_dvsa.py` (new), `tests/fixtures/dvsa_sample.csv` (new).
- Downloads `cfg.discovery.dvsa.url` (default: the gov.uk `active-mot-stations.csv` asset) into `leadforge_data/cache/dvsa/`, refreshed after `refresh_days`; cp1252 decode with replacement; columns `Site_Number, Trading_Name, Address1..3, Town, Postcode, Phone, Class_1..Class_7`.
- `fetch(query)` filters rows whose `Town` equals the query area locality (casefold, first comma segment) or whose postcode district is inside the tile bbox when a tile is given (needs a postcode-district centroid table only if cheap; otherwise Town match — say which in the digest). Emits `RawListing(provider="dvsa")` with data `name, phone, address, complete_address{street,city,postal_code,country="United Kingdom"}, category="MOT test station", categories=[...classes...], site_number`. Registers its field map. `supports_tiles=False`.
- Acceptance: fixture CSV with 6 rows → 3 for "Leeds"; names title-cased (`M AND T TRANSMISSIONS LIMITED` → `M and T Transmissions Limited`); phone E.164; a second fetch uses the cache without network (httpx transport mocked).

**C1 — Extraction truth.** Owns `src/leadforge/enrich/extract.py`, `src/leadforge/enrich/crawler.py`, `src/leadforge/enrich/validate.py`, `tests/test_extract.py`, `tests/test_extract_truth.py` (new).
- Strip `<style>`, `<script>`, `<noscript>`, `<template>` before regex email extraction (mailto/cfemail still parsed from the full document).
- `JUNK_LOCALPARTS` (test, sample, demo, example, someone, yourname, user, name, email, noreply, no-reply, postmaster, abuse, webmaster, hostmaster, root, admin@example) → dropped at extraction; `validate_email` returns `invalid/placeholder` for them regardless.
- `classify_email_affinity(email, business_domain, business_name_norm, people_names) -> Literal["own_domain","freemail_linked","freemail_unlinked","foreign"]`: linked when the local part shares a token (>=3 chars) or initials with the business name, or matches a person name in either `First Last` or `Last, First` order.
- `email_context(text, email, window=90) -> str`: the surrounding text window for evidence.
- Booking: `crawler.compute_signals` broadens `booking_hint` (book + {now, online, appointment, service, mot, your, a slot} within 4 words either order; known platforms: bookmygarage, whocanfixmycar, autodata booking, kwik-fit, calendly, acuity, squarespace-scheduling, setmore, simplybook; iframe/anchor hosts) and records `booking_source`.
- Site identity: signals `final_host`, `offsite_redirect` (final host differs from the business domain, www-insensitive), `http_status`.
- People: `extract_people` and `extract_people_ner` skip candidates whose window contains review markers (`review`, `rating`, `stars`, `★`, `recommend`, `thank you`, `great service`, `google`, `trustpilot`, `/5`) or first-person praise, and names equal to form labels. Candidate gains `context` ("team"|"other").
- `rank_email_contacts(contacts) -> list[row]`: own-domain valid > own-domain role > freemail_linked valid > inferred > risky > unknown > invalid (never freemail above own-domain).
- Acceptance: unit tests for each; the live examples in the report (impallari template credit inside a `<style>` block, `test@gmail.com` in a script array, "Book A Service" anchor, a "Customer Reviews" block) are fixture cases.

**C2 — Enrichment and registry truth.** Owns `src/leadforge/enrich/runner.py`, `src/leadforge/providers/registry.py`, `src/leadforge/enrich/dm.py`, `tests/test_registry.py`, `tests/test_runner_truth.py` (new).
- `name_similarity(business_name_norm, company_name) -> float` (token Jaccard after stripping legal tokens, max with char ratio); a match is accepted only if `>= cfg.registry.min_name_similarity` AND locality overlap; `cfg.registry.active_only` rejects `company_status != active`. `lookup()` and `lookup_with_profile()` share one code path; the profile (number, legal name, status, incorporation, SIC, similarity) is persisted on BOTH the crawl path and the site-less path.
- `_persist`: `crawled_at` only when `res["ok"]`; otherwise `attempted_at` + `error`. Email evidence snippet = `email_context(...)` with `ref_id` set to the contact row id. Emails classified with `classify_email_affinity`; `freemail_unlinked` stored tier `risky` (meta reason), `foreign` dropped; `contacts.affinity` written. GBP: `enrich.gbp.booking_links` non-empty → `signals.booking_hint=True, booking_source="gbp"`; `reply_signatures`/`review_names` → `people` rows `labeled_by="gbp"`, `origin="gbp"`, snippet from the reply, source_url = maps_url. `phone_confirmed` signal when a site phone equals the Maps phone.
- `people.origin` set on every insert (heuristic|registry|gbp); `dm.export_batch` includes `origin` per candidate; `apply_labels` keeps `origin` when setting `labeled_by='agent'`.
- Auto-pick (ADR-010) only when the profile is active and the similarity gate passed.
- Acceptance: fixture Companies House search returning a same-locality company with an unrelated name is rejected; a dissolved company is rejected; a crawl failure leaves `crawled_at` absent and `attempted_at` set; an email evidence row carries a >40-char snippet and a `ref_id`; a freemail address unlinked to the business lands as `risky`.

**D — Scoring and export truth.** Owns `src/leadforge/score.py`, `src/leadforge/data/scoring.default.yaml`, `src/leadforge/data/category_aliases.yaml` (new), `src/leadforge/export.py`, `tests/test_score.py`, `tests/test_export_honesty.py`, `tests/test_export_columns.py` (new).
- Category aliases: a packaged table mapping vertical keywords to Google category strings (auto repair, MOT, dental, real estate, accounting, law, plumbing, electrical, restaurant, gym, salon) plus a token-overlap fallback (shared significant token → 0.6). Acceptance: for the auto ICP, "Car inspection station", "Car repair and maintenance service", "MOT centre", "Auto body shop" → 1.0.
- Split scores: default profile emits `fit` (industry 25, need 25, size 10, geography 10, business_model 10, data_confidence 20 = 100) and `contactability` (DM 30; email: own-domain valid 30 / own-domain role 22 / freemail_linked 20 / inferred 8 / risky 0; validated phone 25; registry corroboration 5; site phone confirmed 5; mobile 3) as meta factors. `total` = fit; tiers from fit with `a_min 80 / b_min 60`; `status` = READY (fit A/B and contactability >= 50) | CALL_ONLY (phone, no eligible email) | RESEARCH | DQ. Hooks fire only when `enrich.crawled_at` is set AND the specific signal key is present; `weak_social_presence` requires `"socials" in enrich`; template texts say only what was observed; `stale_site` text drops "broken pages". Chain penalty uses `db.chain_map`. The `group` penalty applies only when `icp.target` has no `mode` or `mode == "local_business"`. A profile registry (`register_profile(name, fn)`) lets Wave 2 add `company`.
- Export: keep every existing column; add `Fit`, `Contactability`, `Status`, `Next Action`, `Entity Type`, `Lawful Basis (Email)`, `Registry Name`, `Registry Match`, `Chain`, `Site Status`, `Email Confidence`, `All Hooks`; best email via `rank_email_contacts`; `Next Action` from `compliance.next_action` (phone-first) and `db.outreach_state_for` (shows the outreach state when a target exists). Summary sheet gains the funnel (sites → any email → own-domain → eligible) and the count per Next Action.
- Acceptance: deterministic scores on the e2e fixture; on a copy of the live DB (read-only, path in the brief) tier A share and Next Action counts are reported in the unit's proof; new columns non-blank per the zero-blank rule.

### Wave 2 — outreach, drafting, company mode (parallel builders, after Wave 1 merges)

**E — Outreach.** Owns `src/leadforge/outreach/` (all files except `cli.py`'s registration line already present), `tests/test_outreach_*.py`, `tests/fixtures/outreach/`.
- `plan`: enrol scored leads as `outreach_targets` (`--tier A,B --campaign --identity --limit`), every exclusion counted by reason (suppressed, no eligible email, entity gate, chain duplicate, dead site, junk).
- `identity add|list`, `mailbox add|list` (config values reference env var NAMES for secrets; nothing secret in SQLite).
- `approve`: `--tier`, `--ids`, `--all-drafted`, `--approver`; binds `approved_hash = draft_hash`; a message edited after approval reverts to `drafted`.
- Transport ABC (`available()`, `send(msg) -> (message_id, response)`), `FileTransport` (writes `.eml` to `leadforge_data/outbox/`, the dry-run default), `SmtpTransport` (stdlib `smtplib` + STARTTLS/SSL; credentials from env var names), adapter registry for future platforms.
- `doctor`: SPF (`-all`), DKIM selector present, DMARC `p=quarantine|reject`, MX for the reply domain, identity has postal address + privacy URL; all via dnspython; fails closed.
- `send`: dry-run default; `--live` requires `outreach.armed: true` AND `--i-am <approver>`; per message: claim with a state transition in one transaction, re-check suppression, eligibility, per-mailbox daily cap and send window, render headers (`List-Unsubscribe` mailto + https, `List-Unsubscribe-Post: List-Unsubscribe=One-Click`, `Message-ID` with a signed token), send at-most-once (a crash leaves `unknown`, never re-queued automatically). Circuit breaker: mailbox pauses at 3% hard bounces or 0.1% complaints over its last 100 live sends.
- `sync`: ingests `leadforge_data/inbox/*.json` webhook spool and IMAP (stdlib `imaplib`) replies; dedupes on `events.dedupe_key`; classifies (bounce_hard, bounce_soft, complaint, unsubscribe, reply:interested|not_interested|wrong_person|ooo|other) deterministically; writes suppression rows with `source`; advances target state; never prints mailbox content (digest counts only).
- `status`: counts by state, caps consumed, breaker status, unknown sends. `outcome add` records an `outcomes` row (channel phone|email, result).
- Acceptance: golden `.eml` from FileTransport with all headers; a suppressed address is never sent even if approved; a message edited after approval cannot be queued; a synthetic bounce and unsubscribe each create a suppression row and a state change; `--live` without arming fails closed; every assertion watched-fail (break the code, see red, restore) and the proof states it.

**F — Drafting.** Owns `src/leadforge/draft/` (all files except the existing `cli.py` registration), `src/leadforge/data/skeletons/*.yaml`, `tests/test_draft_*.py`, `skills/generate-leads/references/drafting.md` (new).
- `draft export --campaign --purpose --max`: one NDJSON packet per enrolled target (<= 350 tokens; measured 159 mean on the live DB): evidenced facts only (each with `source` URL + `observed_at`), offer, sender persona, purpose, constraints, `name_policy` result (gated name or company-level), personalisation grade A/B/C. Batch header once.
- Purposes: `gainlev_leadgen`, `client_campaign`, `follow_up`, `re_engagement`, `referral`. Each a packaged skeleton YAML: fixed text with two model slots (`subject`, `observation` citing exactly one `used_fact`); identity, postal address, opt-out and the Article 14 line are interpolated by the CLI, never written by the model.
- `draft apply --in drafts.ndjson`: runs the mechanical gate (every number, email, URL, salutation name and multi-word proper noun must appear in the packet; banned-claim regex; negation consistency; length caps), stores `messages` rows `drafted` (gate passed) or `rejected` (reasons in `gate_json`), records `grade` and `used_fact`; `insufficient_evidence` is a valid, counted result.
- `draft render --out drafts/` writes reviewable `.txt`/`.eml` files. `draft check` runs the gate on a file without storing.
- Acceptance: 12-mutation watched-fail suite (each injected fabrication rejected; each restored draft passes); packet token bound test; name policy test (registry name unlinked → company greeting); worked example drafts for the three archetypes in the report generated from fixture rows.

**H — Company mode (GainLev's own pipeline).** Owns `src/leadforge/providers/companies_house.py` (new), `src/leadforge/enrich/resolve_domain.py` (new), `src/leadforge/company.py` (new planner + rubric), `src/leadforge/intake.py`, `src/leadforge/models.py` (Target.mode, sic_codes, incorporated_from/to), `src/leadforge/grid.py` (build_plan dispatch only), `tests/test_company_mode.py` (new), `tests/fixtures/ch_advanced_search.json` (new), `config/icp.company.example.yaml` (new), `skills/generate-leads/references/icp-guide.md` (company-mode section).
- Provider: `GET /advanced-search/companies` with `sic_codes` (repeatable), `location`, `company_status=active`, `company_type`, `incorporated_from/to`, paging `size/start_index`; shares `registry._CH_BUCKET`; stops a shard at `max_hits_per_shard` and reports it; emits `RawListing(provider="companies_house")` with a registered field map; SIC 82200 excluded by default (owner decision 7).
- ICP: `target.mode: local_business|company`; company mode requires `sic_codes` and areas; `intake` validates and compiles; `build_plan` dispatches to `company.build_plan` (SIC group × location shards).
- Domain resolution (free only): slug candidates from the legal name (`.co.uk`, `.com`, `.uk`), verified by a crawler fetch that finds the postcode, the legal name (minus legal tokens) or the company number on the page; evidence row `domain_resolved`; unresolved stays site-less (registry stage still runs). No search-engine scraping.
- Company rubric (`register_profile("company")`): industry fit from SIC, incorporation age band, new-director trigger (officers `appointed_on` within 12 months), share-allotment filing (SH01) as a moderate trigger, hiring signal from crawled careers pages mentioning sales/SDR/BDR/outreach; no review-count sizing; no `group` penalty.
- Acceptance: fixture advanced-search page normalizes to businesses with `source="companies_house"`; a 3-shard plan is generated for one area and two SIC groups; slug resolution verifies a fixture page by postcode and rejects one without; a company ICP compiles and scores deterministically.

## Conventions for every builder

- One writer per file. Touch only the files your unit owns; if you need a change elsewhere, write it as a **request** in your report, do not make it.
- Code against the Wave 0 interfaces exactly as named here. Do not rename them.
- Every new assertion is watched-fail: break the code it covers, see the test red for the right reason, restore. Say so in the proof, per test.
- Never weaken a politeness or compliance invariant to make a test pass (`icm/SCOPE.md`).
- Style: Python 3.11+, pathlib, `shell=False`, pydantic v2 at boundaries, no new runtime dependencies. `ruff check` clean on your files.
- Report: files changed, tests added, the exact gate command and its last line, what is UNPROVEN, and one durable lesson.
